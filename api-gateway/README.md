# api-gateway (Spring Cloud Gateway)

Single entry point for all PhotoConnect API traffic. Reactive (Netty + WebFlux). Pulls config from `config-service`, registers with `discovery-service`, fans out to the three backend services via `lb://` URIs.

## Responsibility

| Concern | Done at the gateway |
|---|---|
| Routing | predicates + filters in `config-repo/api-gateway.yml` |
| Service discovery | `lb://AUTH-SERVICE` → Spring Cloud LoadBalancer + Eureka |
| Correlation IDs | `CorrelationIdFilter` (generate-or-propagate `X-Correlation-Id`) |
| CORS | `spring.cloud.gateway.globalcors` — single source of truth |
| Tracing | Micrometer Tracing → Zipkin (every request becomes a span) |
| Aggregated Swagger | one UI showing every downstream service's OpenAPI |
| JWT validation | **Step 4** (after auth-service exists) |
| Rate limiting | Phase 2 (Resilience4j) |

## Endpoints

| URL | Returns |
|---|---|
| `GET http://localhost:8080/actuator/health` | UP if gateway is alive |
| `GET http://localhost:8080/actuator/gateway/routes` | list of all configured routes |
| `GET http://localhost:8080/swagger-ui.html` | aggregated Swagger UI (will populate as services come online) |
| `GET http://localhost:8080/api/v1/auth/**` | proxied to AUTH-SERVICE |
| `GET http://localhost:8080/api/v1/photographers/**` | proxied to PHOTOGRAPHER-SERVICE |
| `GET http://localhost:8080/api/v1/customers/**` | proxied to CUSTOMER-SERVICE |
| `GET http://localhost:8080/api/v1/inquiries/**` | proxied to CUSTOMER-SERVICE |

## Run it locally

You need `discovery-service` and `config-service` already running:

```powershell
# Terminal 1
.\pc.ps1 discovery-run

# Terminal 2
.\pc.ps1 config-run

# Terminal 3
.\pc.ps1 gateway-run
# or:  mvn -pl api-gateway spring-boot:run
```

Now:

```bash
# Gateway is up
curl http://localhost:8080/actuator/health
# → {"status":"UP"}

# See the routes the gateway loaded from config-service
curl http://localhost:8080/actuator/gateway/routes | jq .

# Try a route — auth-service doesn't exist yet, so this returns 503.
# (That's expected; it proves the gateway TRIED to route to AUTH-SERVICE
# via Eureka and found no live instance.)
curl -i http://localhost:8080/api/v1/auth/login

# Correlation ID is auto-generated by the gateway
curl -i http://localhost:8080/actuator/health | grep -i correlation
# → X-Correlation-Id: <some-uuid>

# Or you can provide your own
curl -i -H 'X-Correlation-Id: my-trace-123' http://localhost:8080/actuator/health | grep -i correlation
# → X-Correlation-Id: my-trace-123
```

Open the Eureka dashboard at <http://localhost:8761> — you'll see `API-GATEWAY` listed.

## Tests

```bash
mvn -pl api-gateway test
```

- `ApiGatewayApplicationTests.contextLoads()` — boots the gateway context with Config + Eureka stubbed out, asserts beans wire up.
- `CorrelationIdFilterTest` — three cases: missing header generates UUID, present header is preserved, blank header generates UUID.
